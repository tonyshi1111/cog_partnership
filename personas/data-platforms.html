Profile

Data platforms are simultaneously building their own coding agents (Snowflake Cortex Code, Databricks AI Dev Kit) AND opening their data context to external coding agents via MCP / AI gateway integrations. The partnership shape is split-personality: Devin can be (a) the agent that calls into Snowflake / Databricks to pull data context for software work, or (b) the agent that builds data pipelines, schema migrations, and data apps for the data platform's customers. Half-partner / half-competitor dynamic is the operating reality.

The platforms have explicit AI partner programs (Snowflake Cortex Code's Claude Code plugin; Databricks Unity AI Gateway supporting Cursor / Codex / Gemini CLI; Brickbuilder Partner Network) but Devin is not yet integrated with either.

Where Cognition wins (2×2)

X-axis: Native data-context awareness (does the agent know your schema, lineage, governance?). Y-axis: Production code execution capability. Cognition + data-platform-partner combo top-right. Cortex Code alone has data-context but limited autonomous execution; Cursor / Claude have execution but lack native data context unless integrated.

Value proposition

Cognition → data platform

Closes the "agent does the work AFTER the data context arrives" loop. Cortex Code can plan; Devin builds and ships. Strengthens the data platform's "control plane for agentic enterprise" narrative with verifiable engineering output.

Data platform → Cognition

Enterprise distribution to data-engineering teams. Snowflake / Databricks have thousands of large-enterprise customers; data-engineering work is high-value (pipelines, migrations, schema work) and historically expensive.
